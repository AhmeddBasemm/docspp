The format is plain YAML with a published schema, so an agent can write it. The **docspp skill** teaches an agent the format, how to set docspp up, how to write good scenarios, and the check-and-look loop that keeps the result honest.

## Install the skill

```sh
npx skills add AhmeddBasemm/docspp --skill docspp        # this project
npx skills add AhmeddBasemm/docspp --skill docspp -g     # every project on this machine
```

This uses the [skills](https://skills.sh) installer, so it works with Claude Code, Cursor, GitHub Copilot, Gemini and the other agents it supports. Add `-a claude-code` to pick one, and `--copy` to copy the files instead of linking them.

Projects made with `create-docspp`, or from the template, already contain the skill in `.claude/skills/docspp`.

## What it knows

- **Setting up**: creating a site, or adding docspp to an existing Astro and Starlight one, and publishing to GitHub Pages.
- **The format**: nodes, groups, edges, views, kinds, icons, and every field they accept.
- **Scenarios and stories**: steps, phases, parallel steps, routes, lookups, the swimlane story view, and how to write ones worth reading.
- **Layout**: which hint fixes which problem, so it changes the model instead of fighting the picture.
- **Troubleshooting**: what every error from `docspp check` means, and the YAML mistakes that cause most of them.

It ships with a complete example diagram that is compiled in the test suite, so the example can never go out of date.

## Using it

Ask in your own words:

> Add a diagram of how checkout works. The code is in `services/`. Include a scenario for a declined card.

> Write the story view for our login flow, with the identity provider and the session store as one lane.

> `pnpm check` is failing on the payments diagram. Fix it.

## The loop it follows

The agent should never guess whether a diagram is valid:

```sh
pnpm docspp list --json            # what exists already
pnpm docspp check --json           # errors with file, line and column, plus suggestions
pnpm docspp icons search kafka     # find an icon name
```

Then it opens the page, looks at the rendered diagram with a browser tool if it has one, and fixes crowding or confusing layout with hints (`rows`, `layout: row`, `w`, `direction`) rather than coordinates.

## Keep diagrams honest

Ask for `refs:` on every node, listing the files it is based on. When the code moves, `docspp check` warns about the stale reference, and a reviewer can see what a change to the diagram should have touched.
