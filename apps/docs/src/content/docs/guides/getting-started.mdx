You need Node 22 or later and [pnpm](https://pnpm.io). The scaffolded project uses pnpm, and `npm create` only runs the scaffolder.

## Create a project

<Steps>

1. Scaffold the project.

   ```sh
   npm create docspp@latest my-docs
   ```

2. Install and start it.

   ```sh
   cd my-docs
   pnpm install
   pnpm dev
   ```

3. Open `http://localhost:4321`. You see a small shop diagram with three scenarios.

4. Open `diagrams/shop/diagram.yaml`, change a title, and save. The page reloads.

</Steps>

If you would rather start from the source, copy `templates/starter` from the [docspp repository](https://github.com/AhmeddBasemm/docspp).

<Aside type="note">
  The folder must not exist yet, or must be empty.
</Aside>

## What you get

```text
my-docs/
├─ diagrams/
│  ├─ diagram.schema.json     editor autocomplete for diagram.yaml
│  └─ shop/
│     ├─ diagram.yaml         nodes, groups, edges, views, scenarios
│     └─ nodes/orders.md      shown when a reader clicks that box
├─ src/content/docs/*.mdx     your pages; embed a diagram with <Diagram name="shop" />
├─ src/styles/custom.css      theme tokens
├─ .github/workflows/         publishes to GitHub Pages
├─ .claude/skills/            a skill that teaches Claude Code the format
├─ astro.config.mjs
└─ package.json
```

Everything you write lives in three places:

| Where | What |
|---|---|
| `diagrams/<name>/diagram.yaml` | The nodes, edges, views and scenarios of one diagram |
| `diagrams/<name>/nodes/<id>.md` | Markdown shown when a reader clicks that box |
| `src/content/docs/**/*.mdx` | The pages around your diagrams |

[Project structure](../project-structure/) explains each file.

## Draw your first diagram

```sh
pnpm docspp new payments
pnpm docspp schema
```

The first command creates `diagrams/payments/diagram.yaml` with a small working example. The second writes the JSON Schema that gives your editor autocomplete. Here is a similar diagram:

```yaml
title: Hello, diagrams

nodes:
  browser: { kind: client, title: Browser }
  api:     { kind: service, icon: nodejs, title: API, sub: ":3000" }
  db:      { kind: database, icon: postgresql, title: Database }

edges:
  - browser -> api: HTTPS
  - api -> db: { kind: data, label: SQL }

scenarios:
  load-page:
    title: Load a page
    steps:
      - browser -> api: GET /items
      - api -> db: { label: SELECT, kind: lookup }
      - db -> api: rows
      - api -> browser: 200 OK
```

Put it on a page with two lines of MDX:

```mdx
import Diagram from '@packagelab/docspp-astro/Diagram.astro'

<Diagram name="hello" />
```

<Diagram name="hello" scenario="load-page" />

Press play, click a box, or drag the canvas. Hold <kbd>Ctrl</kbd> or <kbd>⌘</kbd> and scroll to zoom. [Your first diagram](../first-diagram/) builds a larger one step by step.

## Check your work

```sh
pnpm check          # validate every diagram; errors point at file:line:column
pnpm check --json   # the same, for scripts and agents
```

The build fails when a diagram has errors, so a broken diagram never reaches your published site. [The CLI reference](../../reference/cli/) lists every command.

## Publish

The project ships a GitHub Actions workflow that builds the site and deploys it to GitHub Pages.

<Steps>

1. Push the project to GitHub.
2. Open **Settings → Pages** and set the source to **GitHub Actions**.
3. Push to `main`. The workflow builds the site and publishes it.

</Steps>

[Publishing](../../embed/publishing/) covers custom domains and other hosts.
